Overview / cloudflared

cloudflared

cloudflared is a Basic connector agent for running Cloudflare Tunnel inside Ploinky box. It exposes router-hosted HTTP and WebSocket surfaces through an outbound tunnel, while Ploinky's router remains responsible for agent routing, authentication, MCP proxying, and policy.

Runtime Shape

The agent uses the official docker.io/cloudflare/cloudflared:latest image and starts the image entrypoint with tunnel --no-autoupdate run. The tunnel credential is provided as TUNNEL_TOKEN inside the container and is sourced from the workspace variable CLOUDFLARED_TUNNEL_TOKEN. The manifest sets readiness.protocol to none because the connector does not provide an agent-local MCP or HTTP readiness surface. 

flowchart LR
    Browser[External browser] --> Cloudflare[Cloudflare edge]
    Cloudflare --> Tunnel[Cloudflare Tunnel]
    Tunnel --> Connector[cloudflared container]
    Connector --> Router[Ploinky router on host.containers.internal:8080]
    Router --> Agent[Router-hosted agent surface]

Route Configuration

Published application routes are configured in Cloudflare, not in the Basic manifest. For the Ploinky router inside Ploinky box, the Cloudflare service URL should be http://host.containers.internal:8080. From inside the connector container, localhost means the connector itself, so localhost:8080 is not the router origin.

Operators should protect the public hostname with Cloudflare Access unless the deployment is intentionally public. The Basic manifest does not create Cloudflare DNS records, Access applications, or hostname routes.

Exposure Boundary

The manifest deliberately does not declare routerAccess, httpServices, guest, ssoProvider, ports, or openPorts. The connector must not be used to tunnel random agent 7000 ports, MCP endpoints, task-status endpoints, internal callback ports, or storage surfaces directly. Those application surfaces stay behind Ploinky's router.

Direct data planes such as LiveKit media, TURN, and OnlyOffice editor ports remain explicit Ploinky box publication decisions. Operators should expose those with command-line flags such as --publish or --webmeet-ports when a specific agent requires a direct port.

The normative contract for this connector is DS003 Cloudflared Tunnel Agent.
