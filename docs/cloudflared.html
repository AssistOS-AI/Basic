Overview / cloudflared

cloudflared

cloudflared is a Basic connector agent for running Cloudflare Tunnel inside Ploinky box. It exposes router-hosted HTTP and WebSocket surfaces through an outbound tunnel, while Ploinky's router remains responsible for agent routing, authentication, MCP proxying, and policy.

Runtime Shape

The agent uses the custom image docker.io/assistos/cloudflared-agent:node24-cloudflared. That image copies the official Cloudflare cloudflared binary into the Ploinky Node runtime so the container can run a supervisor process and the bundled Ploinky AgentServer sidecar. The tunnel credential is provided as TUNNEL_TOKEN inside the container and is sourced from the workspace variable CLOUDFLARED_TUNNEL_TOKEN in the production profile. The manifest uses MCP readiness so Ploinky verifies the admin control plane.

Profiles And Dashboard

The default profile keeps TUNNEL_TOKEN required for production. The local-test profile overrides that variable with an empty optional value so a scratch Ploinky box can start the admin MCP sidecar and Explorer dashboard without a real Cloudflare tunnel token. In that mode the supervisor reports missing-token and does not create a live edge tunnel.

Explorer discovers the admin-only settings panel from cloudflared/manifest.json and the cloudflared/IDE-plugins/cloudflared-settings/ bundle. The panel calls /cloudflared/mcp through the router for status, route validation, and route application. It does not display raw tunnel tokens or add direct HTTP service exposure to the agent.

Route Configuration

Published application routes are configured through the admin-only MCP tools and applied to Cloudflare when the required Cloudflare API settings are present. For the Ploinky router inside Ploinky box, the Cloudflare service URL should be http://host.containers.internal:8080. From inside the connector container, localhost means the connector itself, so localhost:8080 is not the router origin.

Operators should protect the public hostname with Cloudflare Access unless the deployment is intentionally public. The dashboard creates DNS records only when the admin explicitly opts in and CLOUDFLARE_ZONE_ID is configured; Cloudflare Access policy remains an operator-owned Cloudflare setting.

Exposure Boundary

The manifest deliberately does not declare routerAccess, guest, ssoProvider, ports, or openPorts. The connector must not be used to tunnel random agent 7000 ports, MCP endpoints, task-status endpoints, internal callback ports, or storage surfaces directly. Those application surfaces stay behind Ploinky's router.

Direct data planes such as LiveKit media, TURN, and OnlyOffice editor ports remain explicit Ploinky box publication decisions. Operators should expose those with command-line flags such as --publish or --webmeet-ports when a specific agent requires a direct port.

The normative contract for this connector is DS003 Cloudflared Tunnel Agent.
