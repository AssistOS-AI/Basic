Overview / web-publishing

web-publishing

web-publishing is the Basic agent that owns Explorer public topology for QA and production. It generates startup config for dependent agents, renders nginx routes, optionally supervises Cloudflare Tunnel, and exposes configuration only through admin settings and admin MCP tools.

Runtime Shape

The agent uses docker.io/assistos/web-publishing-agent:node24-nginx-cloudflared. The container runs node /code/runtime/supervisor.mjs and the bundled Ploinky AgentServer sidecar. The default profile publishes nginx only on 127.0.0.1:8081; the separate lan profile is the explicit reviewed path for binding that data-plane port to all interfaces.

Provider Outputs

Web Publishing emits public topology values through Ploinky's startup config-provider contract before dependent agents resolve their environment. Outputs include OnlyOffice public/callback URLs and WebMeet public signaling/TURN host values. The scoped tunnel token variable is WEB_PUBLISHING_CLOUDFLARED_TUNNEL_TOKEN and is treated as sensitive.

Generated or shared-generated service secrets stay with their owning agents. Web Publishing must not output WEBMEET_LIVEKIT_API_KEY, WEBMEET_LIVEKIT_API_SECRET, WEBMEET_TURN_PASSWORD, PLOINKY_WEBMEET_MASTER_KEY, ONLYOFFICE_JWT_SECRET, or JWT_SECRET.

Operator-facing inputs use Web Publishing-scoped names such as WEB_PUBLISHING_BASE_DOMAIN, WEB_PUBLISHING_PUBLIC_URL, and WEB_PUBLISHING_CERT_EMAIL. Public topology names like WEBMEET_CERT_EMAIL are generated outputs.

Cloudflare Modes

In token mode, the supervisor starts cloudflared tunnel --no-autoupdate run --token <token> when the scoped token is configured. In API mode, admin MCP tools can plan and apply remote tunnel ingress using Cloudflare account credentials. DNS record changes are never automatic: the admin must opt in and provide a zone id.

API-created tunnel tokens are kept out of MCP responses and status files. The agent stores the token in its private secret-state file and the startup provider hands it to Ploinky as the sensitive scoped tunnel-token output.

Cloudflare HTTP tunnels can carry HTTP and WebSocket signaling. LiveKit and TURN media still require explicit media-plane publication in the WebMeet infra agent.

Explorer Cutover Boundary

Explorer QA and production profiles should enable basic/web-publishing global and list it as a startup config provider. They should not keep the old basic/cloudflared dependency as a fallback for public topology.

The normative contract is DS004 Web Publishing Agent.
