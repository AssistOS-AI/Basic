Overview / web-publishing

web-publishing

web-publishing is the Basic agent that owns Explorer public topology for QA and production. It generates startup config for dependent agents, renders nginx routes, optionally supervises Cloudflare Tunnel, and exposes configuration only through admin settings and admin MCP tools.

Runtime Shape

The agent uses docker.io/assistos/web-publishing-agent:node24-nginx-cloudflared@sha256:f0f83dc406bc0434ccbeac48dc826cdb8c527a637a5bf1b5ddf915110d24c477. The container runs node /code/runtime/supervisor.mjs and the bundled Ploinky AgentServer sidecar. Every profile maps AgentServer container port 7000 first through stable loopback-only port 127.0.0.1:17003, so the generic MCP route cannot resolve to Nginx. The sidecar starts only after Nginx accepts TCP on container loopback port 8081, then Ploinky checks MCP readiness. The default profile publishes Nginx on 127.0.0.1:8081 plus the external-proxy connector on 127.0.0.1:18083. The separate lan profile is the explicit reviewed path for binding only port 8081 to all interfaces; the proxy connector and AgentServer remain on host loopback.

The manifest uses primary webmeet-signaling and secondary office-publishing attachments. Ploinky derives the DNS names web-publishing, livekitserveragent, and onlyoffice from canonical agent ids; manifests declare no aliases. Nginx reaches the router at ploinky-router:8080, OnlyOffice at onlyoffice:8080, and LiveKit at livekitserveragent:7880. These are DNS identities, not implicit port mappings, and host-gateway upstreams are not accepted.

Persistent /data uses sticky mode 01777 with Podman ownership transfer disabled, so the image's non-root UID 999 can write a fresh Linux Docker or rootless Podman bind mount without changing host ownership. Config and status stay non-secret and host-readable; the container-owned secret-state.json stays 0600 and is never read by the host-side provider.

Admin MCP schemas enumerate every supported nested config, tunnel, and exposure field. This preserves drafts through AgentServer's strict schema conversion while stripping undeclared properties; bare nested object schemas are not used.

Nginx is always required. Token mode and provisioned API mode require Cloudflared. An API topology without a tunnel keeps the admin control plane available but reports awaiting-provision, never a healthy published data plane. A required child exit or process error records failed status, terminates the other child within a bounded deadline, and exits the supervisor nonzero. Plain Nginx mode records Cloudflared as disabled. SIGINT and SIGTERM perform bounded shutdown with SIGKILL escalation instead of leaving an idle supervisor alive after its data plane disappears.

Provider Outputs

Web Publishing emits public topology values through Ploinky's startup config-provider contract before dependent agents resolve their environment. Canonical WebMeet outputs keep the planes separate: WEBMEET_PUBLIC_LIVEKIT_URL is the wss://meet.<base-domain> signaling URL, WEBMEET_LIVEKIT_NODE_IP is the explicit media IP, WEBMEET_TURN_HOST is the DNS-only turn.<base-domain> hostname, WEBMEET_TURN_EXTERNAL_IP is the explicit relay IP, and WEBMEET_TURN_ALLOWED_PEER_IPS is the media IP as one /32. Coturn derives its realm from the TURN hostname; Web Publishing does not emit a separate realm value. Local mode explicitly emits WEBMEET_TURN_HOST=127.0.0.1 so an old public TURN hostname is replaced rather than left in Ploinky's provider state. The scoped tunnel token variable is WEB_PUBLISHING_CLOUDFLARED_TUNNEL_TOKEN and is treated as sensitive when it is already present in the provider's resolved environment; the provider does not source it from container secret-state.

Generated or shared-generated service secrets stay with their owning agents. Web Publishing must not output WEBMEET_LIVEKIT_API_KEY, WEBMEET_LIVEKIT_API_SECRET, WEBMEET_TURN_PASSWORD, PLOINKY_WEBMEET_MASTER_KEY, ONLYOFFICE_JWT_SECRET, or JWT_SECRET.

Operator-facing inputs use Web Publishing-scoped names such as WEB_PUBLISHING_BASE_DOMAIN, WEB_PUBLISHING_TLS_EDGE, WEB_PUBLISHING_LIVEKIT_MEDIA_IP, and WEB_PUBLISHING_TURN_EXTERNAL_IP. An external edge additionally requires deployment-owned WEB_PUBLISHING_EXTERNAL_PROXY_CIDRS containing only exact /32 or /128 proxy peers; dashboard drafts cannot broaden that trust list. Unconsumed compatibility values are not generated as provider outputs.

Persisted normalized exposure service fields are derived from originId, not custom upstream configuration. The shared provider/supervisor merge path recomputes them before validation, so a same-domain upgrade adopts the current private LiveKit DNS endpoint without discarding operator-owned hostname or path fields.

Deployment env is authoritative over saved dashboard topology. The provider, supervisor, and saved-state tools use one merge contract. A missing config file contributes no local defaults, and changing the env-owned base domain discards concrete old-domain exposures so served routes and provider output stay on one topology. Explicit validation and apply request payloads remain authoritative for the requested operation.

Apply uses an explicit restart boundary rather than claiming an unsafe cross-process hot reload. The supervisor publishes a non-secret fingerprint of the normalized topology and connector identity it launched. That identity contains only connector source, token presence, tunnel id, and tunnel name—never the credential itself. The dashboard preserves those hidden non-secret fields after refresh so API bootstrap followed by a restart can use the ordinary apply flow. A changed draft is persisted with applied: false and restartRequired: true, and tunnel apply makes zero Cloudflare HTTP requests until the active fingerprint matches. A matching unprovisioned API topology may create a tunnel token without changing ingress or DNS, then requires a restart. Only after the matching fingerprint, Nginx, and Cloudflared all report running may a later apply change remote routing. Atomic files and cross-process locks serialize the comparison with config changes. Fixed listener addresses and ports are not mutable draft fields.

LiveKit Signaling Boundary

Nginx proxies only the slash-delimited /rtc boundary to the private livekitserveragent:7880 endpoint on the private webmeet-signaling trust zone. The exact path and required descendants such as /rtc/v1 and /rtc/v1/validate are accepted. Lookalikes such as /rtcevil, plus /twirp, /webhook, other unmatched paths, and unmatched host headers return 404. Both signaling locations are limited to 5 requests per second with burst 20 and 50 concurrent connections per effective client IP; access and upstream error logging are disabled there so participant JWT query values do not enter Nginx logs.

The published local/LAN listener is port 8081. Cloudflare connects through a separate loopback-only 127.0.0.1:18081 listener. Only that connector listener trusts CF-Connecting-IP, and only from loopback; a missing client identity is rejected. Cloudflare ingress never targets raw LiveKit port 7880.

An operator-managed TLS proxy connects through the separately published 127.0.0.1:18083 listener. It must terminate a trusted certificate for the canonical meet. hostname, preserve that Host value, validate the network client address, and overwrite X-Real-IP on every request. The connector rejects every original socket peer not listed in the exact deployment proxy allowlist with 403 before trusting that header; this includes arbitrary sibling containers. A listed peer with a missing identity receives 400. The validated address drives request and connection limits. Raw port 8081 returns 404 for public LiveKit signaling and never trusts forwarded identity headers. Port 18083 must not be exposed publicly.

Configurable non-LiveKit exposure paths accept only simple URI paths made from slashes, unreserved characters, and valid percent-encoded octets. Whitespace, quotes, fragments, variables, and Nginx directive metacharacters are rejected before configuration rendering.

Cloudflare Modes

In token mode, the supervisor starts pinned Cloudflared 2026.7.1 with an ephemeral --token-file held in a private 0700 directory at mode 0600. The token is absent from child argv, child environment, logs, and status; Nginx also receives an environment with Cloudflare secrets removed. In API mode, admin MCP tools can plan and apply remote tunnel ingress using Cloudflare account credentials. DNS record changes are never automatic: the admin must opt in and provide a zone id.

API-created tunnel tokens are kept out of MCP responses and status files. The agent stores the token in its private secret-state file for the container supervisor and does not promote it into Ploinky's host-side provider store.

Cloudflare HTTP tunnels can carry HTTP and WebSocket signaling. LiveKit and TURN media still require explicit media-plane publication in the WebMeet infra agent.

Explorer Cutover Boundary

Explorer QA and production profiles should enable basic/web-publishing global and list it as a startup config provider. They should not keep the old basic/cloudflared dependency as a fallback for public topology.

The normative contract is DS004 Web Publishing Agent.
