# Web Publishing

`basic/web-publishing` owns Explorer public topology for QA and production profiles. It runs nginx as a local data-plane normalizer, can supervise `cloudflared` when a scoped tunnel token is present, and exposes its control plane only through Explorer admin settings and admin MCP tools.

The agent intentionally does not declare public router routes, guest access, SSO provider behavior, or a public dashboard HTTP service. LiveKit and TURN media ports remain explicit media-plane exposure in the WebMeet infra agent.

Admin tools declare every supported nested configuration, tunnel, and exposure field explicitly in `mcp-config.json`. This preserves those fields through AgentServer's strict schema conversion while stripping undeclared input; a bare nested object schema would erase the draft before validation or apply.

The Ploinky AgentServer remains a separate control plane on container port `7000`, mapped first through the stable loopback-only socket `127.0.0.1:17003`. This makes the generic Ploinky MCP route target AgentServer instead of the first Nginx listener. The sidecar waits for Nginx to accept TCP on `127.0.0.1:8081` before it starts, and Ploinky then performs MCP readiness on the protected control mapping. Nginx keeps its existing `8081` data-plane publication; no profile may bind the AgentServer mapping to a non-loopback address.

The agent joins two explicit Ploinky trust zones: primary `webmeet-signaling` for `livekitserveragent:7880` and secondary `office-publishing` for `onlyoffice:8080`. Router traffic uses the generic `ploinky-router:8080` gateway. Ploinky derives the `web-publishing`, `livekitserveragent`, and `onlyoffice` DNS names from canonical agent ids; manifests declare no aliases, and every upstream URL includes its port. The origin allowlist rejects host-gateway and undeclared sibling addresses.

Nginx is a required data-plane child. If it cannot start, exits, or reports a process error, the supervisor writes a failed status, terminates any tunnel connector, and exits nonzero so container-level supervision cannot retain a false-healthy publishing service. Token mode and provisioned Cloudflare API mode require both a scoped tunnel token and a live `cloudflared` child. API mode without a tunnel keeps Nginx and the admin control plane alive under the explicit overall state `awaiting-provision`; it does not report the publishing data plane as running. Plain Nginx mode records the connector as disabled and never starts it. Before spawning the connector, the supervisor writes its token into an ephemeral `0600` file inside a private `0700` directory and passes only `--token-file`; the real token is absent from child argv, child environment, and status. It also removes Cloudflare credential variables from its own mutable environment immediately after capturing the startup token. Nginx receives a copy of the runtime environment with Cloudflare secrets removed. `SIGINT` and `SIGTERM` initiate bounded child shutdown, escalate a child that does not exit to `SIGKILL`, and then terminate the supervisor instead of leaving an idle process behind.

Local/default mode serves the OnlyOffice editor at `http://office.localhost:8081` and the signaling base URL at `ws://127.0.0.1:8081/rtc` through the same loopback-only Nginx listener. Public mode likewise reserves the root of `office.<baseDomain>` for OnlyOffice; custom Office hosts and path mounts are rejected so the provider URL and Document Server assets/WebSockets cannot diverge. The Office route replaces the retired direct OnlyOffice host port, and Nginx preserves the original host and `:8081` port in `X-Forwarded-Host` so Document Server generates reachable browser URLs. The signaling route proxies that exact path and its slash-delimited descendants, including `/rtc/v1` and `/rtc/v1/validate`, while rejecting lookalikes such as `/rtcevil`. Local provider output explicitly replaces stale public OnlyOffice and TURN values with `ONLYOFFICE_PUBLIC_URL=http://office.localhost:8081` and `WEBMEET_TURN_HOST=127.0.0.1`; it does not publish local external-IP or peer-allowlist values. Public mode requires all of these explicit inputs:

| Input | Contract |
| --- | --- |
| `WEB_PUBLISHING_BASE_DOMAIN` | Generates distinct `meet.` signaling and `turn.` relay hostnames. |
| `WEB_PUBLISHING_TLS_EDGE` | `cloudflare` for a Cloudflare mode or `external` for an operator-managed trusted TLS edge. |
| `WEB_PUBLISHING_LIVEKIT_MEDIA_IP` | Canonical unicast, non-loopback LiveKit media IPv4; also generates the Coturn peer ACL as one `/32`. |
| `WEB_PUBLISHING_TURN_EXTERNAL_IP` | Canonical unicast, non-loopback Coturn IPv4 and DNS-only `turn.` A-record target. |
| `WEB_PUBLISHING_EXTERNAL_PROXY_CIDRS` | Required only for `external` TLS: comma-separated exact proxy peers (`/32` or `/128`, at most 16). Deployment-owned; dashboard/MCP drafts cannot broaden it. |

Invalid or incomplete public configuration fails startup. Web Publishing never advertises `wss://` merely because a hostname exists.

Deployment env is authoritative over saved dashboard topology. Provider output, Nginx supervision, and saved-state tools use the same merge contract; a first start with no config file consumes env directly, and changing the env-owned base domain regenerates canonical exposures instead of retaining old saved hostnames.

Configuration persistence does not pretend to hot-reload the independently supervised Nginx and Cloudflared processes. The supervisor publishes a non-secret fingerprint of the topology and connector identity it actually started (`source`, token-presence flag, tunnel id, and tunnel name; never a credential). An apply whose normalized runtime fingerprint differs is saved with `restartRequired: true`; tunnel apply then returns before its first Cloudflare HTTP request, including tunnel creation, and the dashboard reports the restart instead of claiming `Applied`. The dashboard retains those hidden non-secret tunnel fields after refresh so the normal API bootstrap → restart → apply flow still matches the active connector. Once the matching API-mode topology is control-ready as `awaiting-provision`, tunnel apply may create the tunnel and private token but cannot change ingress or DNS; that new connector credential requires a restart. Only a subsequent apply with the matching fingerprint, overall `running` state, and both Nginx and Cloudflared running may update remote ingress and optional DNS. Config, status, and secret files use atomic replacement and cross-process locks, while config and tunnel apply share an operation lock so a concurrent draft cannot race a remote mutation. Fixed listener addresses/ports are not draft fields; unsupported `lanHost` and `listenPort` values are neither accepted nor persisted.

Use `WEB_PUBLISHING_CLOUDFLARED_TUNNEL_TOKEN` for token-mode tunnel startup. The legacy unscoped tunnel token name is not a Web Publishing input or output.

The `/data` bind mount uses manifest mode `01777` (sticky world-writable) with Podman ownership transfer disabled. This lets the image's non-root UID 999 write fresh Linux Docker and rootless Podman volumes while keeping the host directory owned by the invoking user. Config and status files are non-secret `0644` state that the host-side startup provider may read. The private `secret-state.json` stays `0600`, is consumed only inside the container, and is never read by the host-side provider.

Cloudflare API apply sends `meet.<base-domain>` through the same-container Nginx listener at `127.0.0.1:18081` and can create `turn.<base-domain>` as an unproxied A record. A remotely managed token-mode tunnel must be configured with that same Nginx origin; it must never target raw LiveKit port 7880. The connector accepts `CF-Connecting-IP` only from the same-container loopback source and rejects `/rtc` when that client identity is missing.

An operator-managed external TLS proxy must terminate a trusted certificate for `meet.<base-domain>`, preserve that Host header, and send signaling to `http://127.0.0.1:18083`. The proxy must validate the network client address and overwrite `X-Real-IP` on every request; it must not pass through a browser-supplied value. Port 18083 is published on host loopback, and Nginx independently checks the original socket peer against `WEB_PUBLISHING_EXTERNAL_PROXY_CIDRS`: unlisted peers (including arbitrary sibling containers) receive 403 before their header can be trusted, while a listed peer missing the header receives 400. Exact host CIDRs keep the 5r/s and 50-connection limits per validated real client without trusting a whole bridge subnet. The connector must not be exposed publicly.

Saved normalized exposure `service` fields are derived cache data, not custom upstream configuration. On startup the shared provider/supervisor merge path recomputes them from `originId`, so existing saved routes use the current canonical trust-zone endpoints before route validation without discarding operator-owned exposure fields.

Cloudflare API-created tunnel tokens are stored in the agent's private secret-state file and consumed by the container supervisor; they are not copied into the host-side provider store. A scoped token already supplied through the provider's resolved environment may still be emitted as the declared sensitive provider output.
